# CartridgeControl 1.1.0

## Оболочка Windows

Electron и Node.js удалены из программы. Окно построено на WPF/.NET 10 с системным Microsoft Edge WebView2, как ThodHUB. Это веб-интерфейс в Windows-оболочке, а не полный перенос всех экранов в XAML. Цвета, меню и действия сохранены. .NET включён в архив; WebView2 Runtime должен быть установлен (он уже нужен для ThodHUB).

При первом открытии существующей базы сохраняется точная копия `Data/Backups/before-first-native.json`. Перед закрытием или перезагрузкой окна программа ожидает сохранения данных. Второй экземпляр не может одновременно открыть ту же базу.

Печать RAW перенесена на прямые вызовы Windows Print Spooler с прежней TSPL-кодировкой Windows-1251. Режим «Драйвер Windows» использует тот же print.exe. Установка драйвера TSC сохранена, с запросом UAC только по кнопке установки.

## Изменения

- Поиск со сканером: HID-последовательности с завершающим Enter декодируются по физическим клавишам US English. Ручной поиск по русским фамилиям сохранён. Поля редактирования имён и комментариев не перехватываются глобальным сканером.
- В поиске и списке принтеров выводятся страницы по 50 записей. Все совпадения доступны кнопками «Назад» / «Далее». Связанные сотрудники, картриджи и ремонты индексируются один раз при изменении данных вместо повторного полного перебора для каждой строки.
- Блокирующие alert/confirm заменены диалогами внутри интерфейса с восстановлением фокуса. Подтверждения удаления сохранены. Запись файлов выполняется асинхронно и последовательно.
- Повторный импорт принтера сохраняет его существующий programId.
- Ошибка чтения базы останавливает загрузку и автосохранение: пустая база не записывается поверх повреждённого файла. Ошибки записи отображаются в интерфейсе.
- Формат database.json остаётся version: 1. Новых ID при сверке не создаётся; ссылки, история, статусы, партии и ремонты не меняются.

## Сверка исходной базы

1. Откройте «Сверка базы» и скачайте шаблон с текущими данными.
2. Подготовьте TXT/CSV в UTF-8 (разделитель `;` или табуляция) либо Excel с одним листом. Первая строка — точные заголовки:
   `МатОтв;ИнвНомер;Подразделение;Тип;Модель;Картриджи;Дата;Стоимость`
3. Инвентарные номера храните как текст, сохраняя ведущие нули. Картриджи в одной ячейке разделяйте запятыми. Пустое значение предлагает очистить поле — оно не означает «пропустить».
4. Нажмите «Загрузить базу». Все номера из текущей базы и файла отображаются постранично. Неизменённые ячейки бледные, изменения жёлтые, принятые зелёные. Дубли блокируют сверку. Новые и отсутствующие номера отмечены и не добавляются/удаляются автоматически.
5. «Заменить» принимает ячейку; «Пропустить» отклоняет её. «Применить все» принимает все найденные изменения, включая ранее пропущенные. До кнопки «Сохранить» основная база не меняется. «Отмена» сбрасывает сверку.
6. «Сохранить» создаёт полную копию текущего состояния в `Data/Backups/before-reference-*.json`, затем записывает принятые изменения. При ошибке копирования запись не начинается. ID и инвентарные номера не редактируются этим режимом. Исторические имена в журнале и списки сотрудников не переименовываются автоматически при замене материально ответственного.

## Обновление

Закройте программу. Сохраните копию всей существующей папки Data. Распакуйте новую версию в отдельную папку и скопируйте туда Data рядом с CartridgeControl.exe. Сначала проверьте работу на этой копии. Архив обновления не содержит рабочую базу. Не запускайте две копии программы с одной и той же папкой Data.

- `npm run test:desktop`: отдельная временная база, реальный WebView2, сохранение файла, резервная копия, ID, история, дополнительные поля и клавиатурный ввод после импорта.
- Рабочая база пользователя отсутствует. Расхождение складского счётчика отложено по просьбе пользователя; логика складов в этом выпуске не менялась.
- `npm run test:native`: точность исходной копии, атомарная запись, ошибки записи, блокировка второго экземпляра и кодировка TSPL.
- Физические сканер и принтер этикеток не проверялись. HID-события проверены автоматическими тестами, печать не изменялась.
